# Perl / CPAN 保守リスク診断 — 事前確認シート（テンプレート）

> **公開するのは質問項目だけです。回答済みのシートには機密情報が含まれる可能性があるため、公開GitHubには保存しないでください。**

## A. 依頼の目的

- 何の業務を支えるPerlシステムですか（公開可能な抽象度で確認）。
- 何が一番困っていますか。障害、更新、引継ぎ、テスト不足など。
- 何を判断するために診断結果が必要ですか。誰が結果を使いますか。

## B. 試験価格の対象に収まるか

- [ ] 対象は1リポジトリ（または1つの限定モジュール群）
- [ ] Perlバージョンと実行環境が1系統
- [ ] 直接依存が概ね20ディストリビューション以内
- [ ] 依存宣言・テスト・CIなど、調査資料が提供可能
- [ ] 深掘り論点を最大5件に絞れる
- [ ] 診断のみを求めており、修正・本番変更・緊急復旧は不要
- [ ] 合計6時間以内の調査枠で価値ある成果を出せる

当てはまらない場合は、対象を絞るか別途見積もる。いずれも受注前に合意する。

## C. 受領候補の資料

- [ ] Perl・OS・コンテナ等の実行条件（例: `perl -V` の非機密部分）
- [ ] `cpanfile` / `cpanfile.snapshot` / `META.*` / `Makefile.PL` / `Build.PL` 等
- [ ] 必要な範囲のコードと利用許可
- [ ] 既存のテスト一覧・実行方法・CI定義
- [ ] 過去の障害・更新時の問題を説明する**匿名化済み**情報
- [ ] 資料のバージョン/コミット識別子

**受け取らない:** 秘密鍵、APIトークン、顧客データ本体、個人情報、不要なログ。必要なら事前にマスク・除外してもらう。

## D. 実施・契約条件

- [ ] 調査対象、環境、論点、除外事項を双方で確認
- [ ] 実行テストの可否・実行場所・使用コマンドについて事前合意
- [ ] 料金55,000円（税込・試験価格）と追加見積もり条件を確認
- [ ] 着手日、納期、納品形式、検収・支払条件を確認
- [ ] 守秘義務・アクセス権・第三者サービスへの送信可否を確認
- [ ] 資料の保存場所、返却/削除方法・時期を合意
- [ ] 成果物の権利、顧客名・事例公表の可否を明確化
